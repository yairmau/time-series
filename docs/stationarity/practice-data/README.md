# Practice temperature data

Generated by `python stationarity/build-practice-data.py` from the repository's IMS files:
`archive/data/jerusalem_2020_10min.csv`, `jerusalem_2021.csv`, and `jerusalem_2022.csv`.
All three identify Jerusalem Centre (the 2020 file uses Hebrew). The 2019 file is a
different station, Jerusalem Givat Ram, and is not joined to this record.

`jerusalem_daily_2020_2022.csv` contains 1,096 daily means, January 2020–December 2022.
`jerusalem_hourly_july_2022.csv` contains 744 hourly means, July 2022.
Temperature is in °C; timestamps retain the source's local standard-time/winter clock.
The `observations` column counts the available ten-minute temperature readings in a bin.
The minimum coverage is 115 readings/day or 4 readings/hour. All supplied bins pass;
there is no interpolation. Values are rounded to six decimal places before both CSV
and browser export so Python and JavaScript receive identical observations.

Run the notebook from `stationarity/`, or download it and both CSVs into one directory.
The CSVs, lab assets, and downloadable notebook are included by Quarto's resource rules.
The data build script also creates `stationarity-practice.ipynb`, a student copy of
the active notebook with saved outputs cleared. Regenerate it after changing the lesson.

Verification: `python stationarity/tests/check_numerics.py /path/to/node-or-deno` compares
the browser ADF statistics, approximate p-values, lag selection, AR coefficients, and
forecasts against statsmodels. ADF uses `regression="c"`, `autolag="AIC"`, and
`maxlag=min(12, n//2-2)`; these are teaching choices, not universal defaults.
